# 临时轨道桥运输仿真

三组维修列车（轻/中/重）依次通过临时轨道桥。玩家在统一仿真时钟内调整
桥墩位置、张力索工况、车辆间隔，并在有限时间窗（t≤40s，仅 2 个名额）内
加固节点。水位上升会侵蚀河道桥墩 P5，单点过载会累积损伤并引发相邻节点
容量折减的连锁失稳；全部列车通过且残余应力比 < 0.35 才算成功。

## 统一仿真时钟

- 固定步长 `STEP=0.1s`，所有物理、水位、故障、命令生效与日志都在步边界发生。
- 伪随机数使用 mulberry32（种子 20261116），RNG 内部状态进入快照，
  同一种子 + 同一命令序列的两次运行逐位一致（测试中以指纹断言）。
- 玩家操作和剧本事件都是带 `at` 时刻的命令，进入同一 `pending` 队列，
  由 `engine.step()` 按时间弹出；非法/越限命令被拒绝并写入事件日志，不改变状态。
- 每 5 步（0.5s）落一份完整快照，失败回放从快照恢复后重新积分，
  可重现同一失稳节点、同一失败时刻与同一应力带。

## 文件结构

- `engine.js`：纯确定性内核（状态、命令、轴载分布、容量折减、损伤、连锁、快照）。
- `scenarios.js`：四个固定剧本 `normal / fault / overlimit / wrongReinforce`。
- `renderer.js`：Canvas 渲染桥面形变、水位、应力色带、张力索、桥墩与列车。
- `audio.js`：Web Audio，振荡频率随峰值应力变化，过载/故障/失稳触发告警音。
- `app.js`：requestAnimationFrame 时钟循环，暂停/单步/恢复/失败回放与面板绑定。
- `../tests/run-tests.js`：Node 断言套件与 JSON 报告。
- `../tests/browser-smoke.js`：无头 Chromium 界面冒烟。

## 物理模型摘要

- 每根车轴按二次影响核（半径 12m）把动态轴载分到相邻节点，
  动态系数 1.12±6%，抖动来自确定性 RNG。
- 节点容量 = 桥面抗弯容量 + 桥墩/桥台/张力索容量 + 加固奖励；
  应力比 `r=需求/容量`，`r≥1` 每步累积 0.22 损伤，损伤满 1 或 `r≥1.6` 立即失稳。
- 节点失稳后移除该节点支撑，并把左右相邻节点容量乘 0.55，模拟连锁传播。
- 水位 `min(28, 1.6t)`；超过 P5 基座 18m 后按 0.035/m 折减健康度（下限 0.18）。
- 泵故障把 P5 容量压到故障上限；张力索/缆索故障按比例折减，均带持续窗口。

## 四个剧本与验证结论

| 剧本 | 关键设置 | 结果 |
| --- | --- | --- |
| `normal` | 加固临界弯矩节点 N1/N9 | 成功，峰值应力比 0.725，残余 0 |
| `fault` | t=22s P5 泵故障，t=34s 修复 | 成功；故障时余量 0.604，窗口最低余量 0.376（t=24s） |
| `overlimit` | 间隔 3、速度 99、节点 99、第三次加固 | 4 条越限命令全部拒绝，状态不被污染，运输仍成功 |
| `wrongReinforce` | 两个加固名额浪费在桥台 N0/N10 | t=15.9s N1 失稳，t=27.3s N9 连锁失稳 |

失败回放从 t=13s 快照重新积分，在 t=15.9s 重现 N1 失稳，
回放应力数组与原运行误差 < 1e-9。故障恢复后继续浸泡 300 步（30s），
断言无新失稳、损伤全部回落、无应力/水位/损伤跳变。

## 运行方式

```bash
node tests/run-tests.js        # 确定性内核 + 四剧本 + 回放 + 浸泡，输出 artifacts/test-report.json
node tests/browser-smoke.js    # 起本地 HTTP 服务并用无头 Chromium 验证暂停/单步/回放
```

浏览器打开 `bridge/index.html`（建议通过本地静态服务，避免 file:// 限制）：

```bash
cd bridge && python3 -m http.server 8791
# 访问 http://127.0.0.1:8791/
```

界面操作：暂停冻结时钟、单步只推进 0.1s、恢复继续实时积分；
“失败回放”仅在失败剧本可用，会从最近快照逐帧重播失稳过程。
