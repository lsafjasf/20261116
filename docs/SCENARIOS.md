# 固定场景与故障路径报告

复现命令（零依赖，仅需 Node 18+）：

```bash
npm test                 # 12 个单元/契约测试
npm run paths            # 四条存档路径 + 写入中断模拟
npm run scenarios        # 三套固定性能场景，输出 JSON 报告
npm run serve            # 浏览器界面，默认 http://localhost:4173
```

机器可读报告：`userdata/reports/scenario-report.json`，完整路径日志：
`userdata/paths-output.txt`。

## 存档四条路径（界面按钮一一对应）

| 路径 | 注入方式 | 恢复行为 | 界面状态 |
| --- | --- | --- | --- |
| 正常保存 | 直接保存 | 主存档校验通过直接加载 | `saved` / `loaded` |
| 损坏文件 | 截断主存档并追加乱码 | 跳过主档，从最近完整备份恢复 | `recovered`，显示 from=backup |
| 旧版本 | 手工注入 v1 信封 | v1→v2→v3 链式迁移，再保存升级 | `loaded`，显示 migration=1→2→3 |
| 空间不足 | 配额小于存档体积 | 写入被拒，原快照保持可加载 | `quota`，标注可恢复 |
| 写入中断 | 首次写临时键即抛 EIO | 临时键清理，主档/备份字节不变 | `save-failed`，标注可恢复 |

版本不受支持（例如 v99）时抛出 `UnsupportedVersionError`，界面给出
“支持 v1..v3”的明确提示，而不是加载错误数据。

## 三套固定性能场景

同一种子 `20261116`、同一批移动目标，仅改变缓存容量与地图参数。

### 优化前（pre，无缓存，容量 0）

- 输出哈希：`D6CB89A1`；分数 100，步数 168，宝石 1。
- 平均帧时间 0.312 ms，候选峰值 34，命中率 0，扩展节点 1730。
- 异常日志：4 条结构化 `UNREACHABLE`（墙体隔绝目标），无崩溃。

### 优化后（post，LRU 容量 256）

- 输出哈希：`D6CB89A1`（与优化前逐字节一致），分数/步数/宝石完全相同。
- 平均帧时间 0.092 ms，命中率 0.5（5 命中 / 5 未命中），扩展节点 865（-50%）。
- 异常日志与优化前深比较一致；堆增量下降，无新增异常类型。

### 边界参数（edge，48×32、墙体 30%、24 宝石、缓存容量 1）

- 输出哈希：`4380FF74`；分数 600，步数 920，宝石 6，候选峰值 75，节点 7372。
- 容量 1 的缓存按预期几乎无命中（18 次未命中），用于验证 LRU 退化为直通时
  不改变路径结果。
- 18 次移动中 3 次不可达，全部转为 `UNREACHABLE` 日志，游戏继续运行。

## 语义不变性结论

- 规范化快照哈希：pre 与 post 均为 `D6CB89A1`，地图、进度、设置、回放摘要
  全部一致。
- 公开数据结构（存档信封、`snapshot()` 形状、设置取值域）未改；缓存属于
  纯内部优化，开关切换不触发任何迁移。
- 视觉与交互未随优化变化：画布渲染、点击寻路、设置控件在两种模式下共用
  同一套代码路径，差异只在内部计数器与缓存统计。
- 错误处理变化仅限存档层：新增临时键、轮转备份与迁移提示；既有游戏内
  `UNREACHABLE` 语义保持不变。
